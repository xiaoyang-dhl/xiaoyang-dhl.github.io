# 06 AI 使用说明

## 6.1 使用工具

本次项目在搭建、排障与文档整理过程中使用了对话式 AI 助手（豆包）作为辅助工具。AI 负责提供原理说明、配置片段、排障方向与文档初稿；所有命令执行、配置写入、账号凭据操作与最终线上发布均由人工在本地完成。

## 6.2 用途与分工

| 环节 | AI 承担的工作 | 人工承担的工作 |
| --- | --- | --- |
| 原理讲解 | 解释 Hexo 静态生成、主题样式注入、gh-pages 发布链路的工作机制 | 对照本地仓库文件核对实际配置与版本 |
| 配置生成 | 生成 _config.yml、_config.next.yml、styles.styl 相关配置片段 | 确认开关、路径与取值后写入本地文件 |
| 问题排查 | 根据报错现象给出可能原因与处置方向（如命令找不到、分支不出现、连接超时） | 在本地复现问题、执行处置命令并验证结果 |
| 样式迭代 | 依据观感反馈给出背景、透明容器、文字阴影与正文底色的调整方案 | 在浏览器预览中确认实际可读性与排版 |
| 文档撰写 | 按对话记录整理产品定义、需求、部署、测试、运维等文档初稿 | 复核文档事实、口径与遗留项，确认与仓库现状一致 |
| 发布操作 | 不参与代码提交、凭据填写与线上部署 | 人工执行构建、推送与 Pages 发布验证 |

## 6.3 关键提示词记录

以下为过程中用于推动任务的代表性提问（已隐去个人敏感信息）：

1. 定位背景未生效：「从第一步换背景开始，我现在还是丝带背景。」
2. 样式可读性迭代：「把旁边的边框背景去掉，中间的白框去掉，但是让字更清楚一些。」
3. 后台选型咨询：「这个博客管理后台是什么？就是可以自己添加删减目录什么的。」
4. 部署链路确认：「我就是要用 deploy 这个部署。」
5. 文档整理：「总结本次全部对话，写一个实施文档，内容包括基本原理、运维方案、实施方法。」
6. 交付物对齐：按课程交付清单要求，整理为产品定义、需求分析、部署实施、测试验收、运维手册、AI 使用说明六份 Markdown 文档。

## 6.4 人工复核与修改记录

AI 产出的内容均经过人工确认或实测后才纳入交付，复核要点如下：

| 项目 | 复核方式 | 结论 |
| --- | --- | --- |
| 丝带特效关闭 | 检查 _config.next.yml 配置与生成页面脚本引用 | 已关闭，页面无丝带脚本引用 |
| 自定义样式注入 | 核对 custom_file_path.style 路径与编译后的 main.css | 样式规则已进入产物样式表 |
| 背景资源落盘 | 核对 source/img/rain-road.jpg 与 public 产物 | 图片已纳入构建 |
| 部署分支配置 | 核对 deploy.repo 与 deploy.branch | 产物分支为 gh-pages |
| Pages 发布设置 | 在仓库 Settings → Pages 核对分支与根目录 | 选择 gh-pages、/(root) |
| 后台凭据 | 仅保留本地配置中的密码哈希与 secret，文档不写明文 | 未在交付文档中记录敏感凭据 |
| 文档事实口径 | 对照仓库版本号、目录结构与当前样式内容复核 | 以本地仓库现状为准 |

## 6.5 使用边界与注意事项

1. AI 给出的命令、配置与样式片段必须在本地构建预览验证后再部署，不能直接视为可上线结论。
2. GitHub 账号、Git 凭据、后台密码等敏感信息不提供给 AI，也不写入公开仓库与交付文档。
3. 网络连通性、账号授权与线上发布等操作由人工执行，AI 仅提供排查思路。
4. AI 生成的文档需人工复核事实与口径；与仓库现状不一致时，以本地仓库为准。
5. 本项目为静态博客，不涉及数据库、容器化与 K8s 部署；AI 未为这些不适用项编造实现内容，相关排除项已在需求分析文档「不做清单」中说明。
