# 05 运维手册

## 5.1 日常发布流程

### 5.1.1 写作与保存

- 方式一：在本地后台 `http://localhost:4000/admin` 的「帖子 / 页面」中编辑，保存后内容写入 `source/_posts` 或对应页面目录。
- 方式二：直接用编辑器修改 source 目录下的 Markdown 文件。

### 5.1.2 本地预览

```bash
hexo clean
hexo g
hexo s
```

在浏览器检查首页、文章页、关于页、标签与分类页，确认排版与文字可读性。

### 5.1.3 发布上线

确认预览无误后执行部署：

```bash
hexo g && hexo d
```

也可在后台 Deploy 页面填写备注后点击部署，其执行命令为 `cmd /c "hexo g && hexo d"`。等待推送完成后，GitHub Pages 自动发布 gh-pages 分支内容。

### 5.1.4 线上验证

1. 打开站点地址。
2. 按 `Ctrl + F5` 强制刷新，排除旧样式缓存。
3. 抽查首页、最新文章与关于页，确认图片、样式与链接正常。

## 5.2 巡检清单

| 检查项 | 检查方式 | 频次 | 正常标准 |
| --- | --- | --- | --- |
| 站点可访问 | 浏览器打开首页 | 每次发布后 | 页面正常打开，无 404 / 500 |
| 背景与样式加载 | 查看页面背景、文字颜色 | 每次发布后 | 背景图显示，文字清晰，无残留旧样式 |
| 图片资源 | 检查头像、背景图是否加载 | 每次发布后 | 图片不裂图、不缺失 |
| 后台可登录 | 本地访问 /admin | 定期 | 可进入管理界面 |
| Git 工作区 | 查看待提交与待部署内容 | 每次发布前 | 改动符合预期，无误提交 |
| 产物分支 | 确认 gh-pages 最新提交时间 | 每次发布后 | 与本次发布时间一致 |
| 磁盘与依赖 | 查看项目目录体积、node_modules 状态 | 定期 | 可正常构建，无依赖损坏 |

## 5.3 备份与恢复

### 5.3.1 备份对象

- 源码与配置：`_config.yml`、`_config.next.yml`、`source/`、`themes/next/`、`package.json`，通过 Git 提交与远程仓库备份。
- 构建产物 `public/` 不纳入日常备份，可由源码重新生成。
- 背景图、头像等静态资源保存在 `source/img/`，随源码一并备份。

### 5.3.2 提交规范

- 每次内容或配置调整后及时提交，提交信息说明本次改动（如「更新简历内容」「调整背景可读性样式」）。
- 源码存放在默认工作分支；gh-pages 为产物分支，由部署命令维护，不要手动编辑其中文件。

### 5.3.3 恢复步骤

1. 在另一台机器安装 Node.js、npm 与 Git，克隆仓库。
2. 执行 `npm install` 恢复依赖。
3. 执行 `hexo clean && hexo g && hexo s` 验证本地可运行。
4. 如需回退到历史版本，从 Git 历史检出对应源码版本后重新部署。
5. gh-pages 内容由下次部署整体覆盖；线上回退通过在本地恢复旧版本后重新部署实现。

## 5.4 配置与样式维护

### 5.4.1 样式参数对照

自定义样式位于 `source/_data/styles.styl`，关键参数如下：

| 规则 / 参数 | 当前取值 | 作用 | 调整建议 |
| --- | --- | --- | --- |
| 背景图地址 | `/img/rain-road.jpg` | 全局固定背景 | 换图时替换为 source/img 下新文件名 |
| 背景铺满 | `background-size: cover`，`background-attachment: fixed` | 铺满视口并固定 | 一般保持不变 |
| 正文字色 | `#ffffff` | 背景上的主文字颜色 | 背景偏亮时可加深文字阴影 |
| 链接颜色 | `#b3f0ff` | 链接在背景上的辨识度 | 与正文保持区分即可 |
| 正文底色 | `rgba(0, 0, 0, 0.20)` | 文章区弱暗色底，提升阅读对比度 | 文字偏浅时适当调高不透明度 |
| 文字阴影 | 两层黑色阴影 | 保证深背景上白字清晰 | 阴影过重导致发糊时减小第二层透明度 |
| 容器背景 | `transparent` | 去掉中间与侧边白框 | 如需恢复卡片式外观可改回半透明白底 |

### 5.4.2 更换背景图步骤

1. 新图片放入 `source/img/`，控制单图体积在数百 KB 以内。
2. 修改 styles.styl 中 `background: url(...)` 的路径。
3. 本地 `hexo clean && hexo g` 后预览确认。
4. 检查文字与新背景的对比度，必要时调整正文底色或阴影。

### 5.4.3 可读性调整原则

- 文字看不清：优先加深阴影或提高正文暗底不透明度，而不是把全局容器重新拉成大白框。
- 画面过暗：降低正文暗底不透明度，或更换亮度更高的背景图。
- 改动样式后必须执行 `hexo clean` 再构建，避免旧产物残留。

## 5.5 常见故障处置

| 故障现象 | 可能原因 | 处置方法 |
| --- | --- | --- |
| 部署报 `Recv failure: Connection` / 连接超时 | 网络无法连通 GitHub | 切换网络（如手机热点）后重试；确认 Git 凭据已配置 |
| 后台部署报 `ENOENT` 命令找不到 | Windows 子进程未识别命令拼接 | deployCommand 使用 `cmd /c "hexo g && hexo d"` 写法；确认 hexo 在命令行可直接运行 |
| 后台页面 404 | 插件未安装或预览服务未重启 | 重新 `npm install hexo-admin --save`，重启 `hexo s` |
| 背景未生效 | 注入路径被注释、样式文件缺失、旧产物缓存 | 检查 `custom_file_path.style` 路径与 styles.styl 是否存在，执行 `hexo clean` 后重新构建 |
| 页面仍是旧样式 | 浏览器缓存或 public 旧产物 | 浏览器 Ctrl+F5 强制刷新；本地清理 public 后重新生成 |
| Pages 分支下拉中看不到 gh-pages | 分支尚未创建 | 先在本地成功执行一次 `hexo g && hexo d`，分支由部署命令自动创建 |
| 部署推送到错误分支 | deploy.branch 配置不当 | 核对 `branch: gh-pages`，不要写成源码分支名 |
| 背景上文字难辨认 | 背景亮部与文字对比度不足 | 按 5.4.3 加深阴影或正文暗底 |
| 4000 端口无法启动 | 端口被占用 | 释放占用端口，或 `hexo s -p 其他端口` |

## 5.6 安全管理

1. 后台仅在本地使用，不要将 `/admin` 直接暴露到公网。
2. 后台密码以哈希形式保存在配置中，仓库内不记录明文密码；`secret` 用于会话校验，视同凭据保管。
3. Git 凭据通过系统凭据管理，不在文档、截图或提交信息中泄露。
4. 定期检查仓库 Collaborator 与部署密钥，移除不再使用的授权。
5. 配置变更提交前复核，避免将个人敏感信息写入公开仓库。

## 5.7 性能与稳定性维护

- 背景图、头像等静态资源控制体积，避免单图过大拖慢首屏。
- 谨慎叠加多个画布 / 动效插件，同时启用过多特效会造成页面卡顿。
- 升级 Hexo 或主题前，先在本地构建预览验证，再部署上线。
- `public/` 与 `node_modules` 为可重建内容，仓库备份以 source、配置与依赖清单为准。
