# 02 需求分析说明书

## 2.1 编写依据

本文档依据「小洋的博客」实际搭建过程与最终配置整理，功能需求与当前仓库实现一一对应；非功能需求结合静态站点特性与个人项目使用场景确定。

## 2.2 功能需求

| 编号 | 需求描述 | 优先级 | 实现位置 / 方式 |
| --- | --- | --- | --- |
| FR-01 | 支持撰写、编辑 Markdown 文章并在站点列表与详情页展示 | 高 | source/_posts 目录，Hexo 文章生成器 |
| FR-02 | 支持独立页面（关于 / 简历） | 高 | source/about/index.md |
| FR-03 | 支持标签、分类、归档导航与页面 | 中 | source/tags、source/categories，对应生成器插件 |
| FR-04 | 侧边栏展示头像、作者信息与导航菜单 | 中 | _config.next.yml 侧边栏与 avatar 配置 |
| FR-05 | 全局使用自定义雨天背景图，背景固定铺满视口 | 高 | source/img/rain-road.jpg，source/_data/styles.styl |
| FR-06 | 背景之上保证文字清晰可读（配色、阴影、正文底色） | 高 | styles.styl 中的颜色与 text-shadow、正文半透明底规则 |
| FR-07 | 关闭默认丝带画布特效，避免与自定义背景冲突 | 高 | _config.next.yml 中 canvas_ribbon.enable = false |
| FR-08 | 提供本地后台面板，可在网页中维护文章与页面 | 中 | hexo-admin，本地地址 /admin |
| FR-09 | 后台可触发构建与部署命令，将静态产物发布到 gh-pages | 中 | admin.deployCommand，hexo-deployer-git |
| FR-10 | 站点通过 GitHub Pages 对外公开访问 | 高 | 仓库 gh-pages 分支，Pages 设置为 gh-pages /(root) |

## 2.3 非功能需求

| 编号 | 类别 | 需求描述 | 衡量方式 |
| --- | --- | --- | --- |
| NFR-01 | 性能 | 首页与文章页在常规网络下可正常打开，背景图体积控制在合理范围 | 背景图约 243 KB；本地预览首页返回 HTTP 200 |
| NFR-02 | 兼容性 | 页面在主流桌面浏览器（Chrome / Edge）下可正常浏览与阅读 | 本地预览人工复核页面排版与文字 |
| NFR-03 | 可维护性 | 内容、样式、部署配置分别落在独立文件，修改路径明确 | 配置文件、_data 样式、Markdown 文章分层存放 |
| NFR-04 | 安全 | 后台仅本地使用，访问需经过密码校验；不在公开仓库泄露明文凭据 | 后台使用密码哈希与 secret；仓库内不保存明文密码 |
| NFR-05 | 稳定性 | 发布链路单一明确，不与其他自动部署机制并行冲突 | 仅保留 gh-pages 产物分支发布方式，无并行工作流 |
| NFR-06 | 可迁移性 | 站点可在另一台装有 Node.js 与 Git 的机器上按部署手册重建 | 依赖记录于 package.json，配置文件纳入源码管理 |

## 2.4 验收标准

1. 本地执行 `hexo clean && hexo g` 可无报错生成静态文件。
2. 本地预览 `http://localhost:4000` 返回 200，首页、关于页、标签页、分类页可打开。
3. 生成结果中不再加载丝带画布脚本。
4. 自定义背景图与样式规则编译进入站点样式表。
5. 后台面板可在本地访问并完成文章保存。
6. 执行部署后静态产物推送到 gh-pages 分支，Pages 可访问更新后的站点。
7. 背景之上正文、标题、链接文字可清晰辨认。

## 2.5 不做清单

以下内容在本期明确排除，后续如需要再单独立项评估：

- 数据库与 SQL 表结构设计、读写接口。
- 容器化交付：Dockerfile、docker-compose.yml。
- Kubernetes 部署清单：Namespace、Deployment、Service、Ingress、ConfigMap、Secret、PVC。
- 在线评论、留言、点赞、订阅与邮件通知系统。
- 多用户注册、角色权限与后台公网开放。
- 移动端 App、小程序与在线图床服务。
- 自定义域名、HTTPS 证书管理与 CDN 配置。
