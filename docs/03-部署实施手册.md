# 03 部署实施手册

## 3.1 架构与数据流

本项目为纯静态站点，本地完成内容编写与构建，静态产物经 Git 推送到 GitHub 仓库的产物分支，由 GitHub Pages 直接对外提供访问。

```
source/（Markdown 文章、页面、图片、_data 样式）
        │  hexo generate（本地构建）
        ▼
public/（HTML / CSS / JS 静态产物）
        │  hexo-deployer-git
        ▼
gh-pages 分支（产物仓库）
        │  GitHub Pages 发布
        ▼
访客浏览器访问站点地址
```

后台 hexo-admin 运行在本地预览服务之上，仅读写本地 source 目录；其部署按钮执行的是本地构建与推送命令，不构成独立的后端服务。

## 3.2 前置条件

| 条件 | 要求 | 检查方式 |
| --- | --- | --- |
| Node.js | 已安装，可运行 npm | `node -v`、`npm -v` |
| Git | 已安装并配置 GitHub 账号凭据 | 可正常 `git` 访问仓库 |
| 仓库权限 | 拥有 xiaoyang-dhl/xiaoyang-dhl.github.io 仓库推送权限 | 可在仓库设置中看到 Pages 选项 |
| 网络 | 可连接 GitHub；普通网络超时时可切换手机热点重试 | 部署命令可完成推送 |
| 依赖 | 项目依赖通过 npm 安装到本地 | 项目根目录存在 node_modules |

## 3.3 目录结构

```
myblog/
├── _config.yml              # 站点信息、部署链路、后台配置
├── _config.next.yml         # NexT 主题配置（侧边栏、特效、样式注入）
├── package.json             # 依赖与脚本记录
├── scaffolds/                # 文章模板
├── source/
│   ├── _posts/              # 文章：hello-world.md、resume.md
│   ├── about/               # 关于（简历）页面
│   ├── tags/                # 标签页
│   ├── categories/          # 分类页
│   ├── img/                 # avatar.jpg、rain-road.jpg
│   └── _data/
│       └── styles.styl      # 自定义样式（注入到主题）
├── themes/next/             # NexT 主题源码
├── public/                  # 构建产物，由 hexo clean 清理
└── .deploy_git/             # 部署插件辅助目录
```

## 3.4 实施步骤

### 3.4.1 安装项目依赖

在项目根目录执行：

```bash
npm install
```

依赖清单见 package.json，核心包括 hexo 7.3.0、hexo-admin 2.3.0、hexo-deployer-git 4.0.0 及文章、标签、分类、归档生成器与渲染器。

### 3.4.2 站点基础配置

在 `_config.yml` 中确认以下项：

```yaml
title: 小洋的博客
subtitle: '记录摸索博客的某一天'
author: xiaoyang
language: zh-CN
theme: next
url: https://xiaoyang-dhl.github.io
```

> 注意：当前仓库中 `url` 仍为占位值 `http://example.com`，上线前应改为实际站点地址，避免站点链接与 RSS 等资源地址异常。

### 3.4.3 主题与侧边栏配置

在 `_config.next.yml` 中确认：

```yaml
scheme: Mist
sidebar:
  position: left
  display: always
avatar:
  url: /img/avatar.jpg
  rounded: true
  rotated: false
```

### 3.4.4 放置背景资源

将背景图放入 `source/img/rain-road.jpg`（当前图片 816×1456，约 243 KB）。图片位于 source 目录下，构建时会自动复制到产物的 `img/` 路径。

### 3.4.5 编写并启用自定义样式

1. 新建 `source/_data/styles.styl`，写入背景、文字颜色、阴影与正文底色规则。
2. 在 `_config.next.yml` 的 `custom_file_path` 中启用样式注入：

```yaml
custom_file_path:
  style: source/_data/styles.styl
```

未取消注释该路径时，主题不会加载自定义样式，这是背景不生效的常见原因。

### 3.4.6 关闭丝带画布特效

在 `_config.next.yml` 中关闭默认丝带动画：

```yaml
canvas_ribbon:
  enable: false
```

### 3.4.7 安装与配置后台

```bash
npm install hexo-admin --save
```

在 `_config.yml` 的 `admin` 段配置访问账号、密码哈希、secret 与部署命令：

```yaml
admin:
  username: xiaoyang-dhl
  password_hash: <bcrypt 哈希值>
  secret: <后台会话密钥>
  deployCommand: cmd /c "hexo g && hexo d"
```

Windows 下部署命令需通过 `cmd /c` 调用，否则后台子进程无法识别拼接命令，会报命令找不到错误。

### 3.4.8 配置部署链路

在 `_config.yml` 中配置 Git 部署：

```yaml
deploy:
  type: git
  repo: https://github.com/xiaoyang-dhl/xiaoyang-dhl.github.io.git
  branch: gh-pages
```

### 3.4.9 首次部署并创建产物分支

在本地执行：

```bash
hexo g && hexo d
```

`gh-pages` 分支由首次部署命令自动创建，无需在 GitHub 网页手动新建。推送成功后，仓库分支列表中才会出现 gh-pages。

### 3.4.10 GitHub Pages 发布设置

进入仓库 Settings → Pages：

1. Source 选择 `Deploy from a branch`。
2. Branch 选择 `gh-pages`，文件夹选择 `/(root)`。
3. 保存，等待 Pages 发布完成后访问站点地址。

### 3.4.11 本地预览验证

```bash
hexo clean
hexo g
hexo s
```

浏览器打开 `http://localhost:4000` 检查首页、关于页、标签与分类页。

## 3.5 预期输出

| 环节 | 预期结果 |
| --- | --- |
| 构建命令 | 输出 `INFO Generated` 与文件统计，无报错退出 |
| 产物目录 | `public/` 下生成 index.html、css/main.css、img/rain-road.jpg 等 |
| 本地预览 | `http://localhost:4000` 返回 HTTP 200 |
| 样式表 | main.css 中包含背景图引用与自定义可读性规则 |
| 部署 | 产物推送到 gh-pages 分支，仓库出现该分支 |
| 线上访问 | Pages 发布后可通过站点地址访问更新后的页面 |

## 3.6 回退方案

| 回退场景 | 操作方式 |
| --- | --- |
| 自定义样式异常 | 注释 `custom_file_path.style` 行，或将 styles.styl 恢复为备份版本，重新 `hexo clean && hexo g` |
| 需要恢复丝带特效 | 将 `canvas_ribbon.enable` 改回 `true` 后重新构建 |
| 配置文件误改 | 从 Git 历史中检出对应版本的 `_config.yml` 或 `_config.next.yml` |
| 线上版本需要撤销 | 在本地恢复到上一可用版本后重新执行部署，gh-pages 会被新产物整体覆盖 |
| 发布链路冲突 | 本项目已移除并行的 Actions 自动部署工作流；不要同时启用 Actions 构建与 hexo-deployer-git 推送，避免分支与页面内容互相覆盖 |

## 3.7 安装期常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| npm install 缓慢或失败 | 网络访问 npm 源受限 | 切换国内镜像源后重试 |
| 4000 端口被占用 | 本地已有其他服务监听 | 释放端口或通过 `hexo s -p 端口号` 指定其他端口 |
| 背景样式未生效 | 注入路径被注释、_data 文件缺失或未清理旧产物 | 检查 3.4.5 配置，执行 `hexo clean` 后重新构建 |
| 后台访问 404 | 插件未安装或预览服务未重启 | 确认依赖已安装，重启 `hexo s` 后访问 `/admin` |
| 部署提示连接失败 | 网络无法连通 GitHub | 切换网络（如手机热点）后重试，参考运维手册故障处置 |
